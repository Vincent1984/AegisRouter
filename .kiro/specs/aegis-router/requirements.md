# AegisRouter — 智能安全 LLM 路由网关 需求规格

## 产品概述

AegisRouter 是一款企业级大模型安全路由中间件，部署在应用层与 LLM API 之间，实现隐私数据脱敏保护、智能成本分流路由、安全合规拦截和高可用灾备调度。

---

## 功能性需求 (Functional Requirements)

### FR-1: 统一网关接入层

- **FR-1.1**: 对外暴露完全兼容 OpenAI SDK 的 `v1/chat/completions` API 端点
- **FR-1.2**: 支持流式传输 (SSE Streaming, `stream=true`)
- **FR-1.3**: 支持 API Key 鉴权，通过 Bearer Token 验证请求合法性
- **FR-1.4**: 支持请求级别的 Rate Limit 限流（按 API Key 粒度）
- **FR-1.5**: 支持多模型后端配置（OpenAI, DeepSeek, 本地模型等），通过 YAML 声明式管理

### FR-2: 隐私脱敏与还原层

- **FR-2.1**: 对输入 Prompt 中的 PII 数据进行实时检测（人名、手机号、身份证号、邮箱、IP 地址、银行卡号）
- **FR-2.2**: 支持中文 PII 识别（中国手机号 11 位格式、18 位身份证号、中文人名）
- **FR-2.3**: 检测到的 PII 用占位符替换（如 `[PERSON_1]`, `[PHONE_1]`），保持语义连贯
- **FR-2.4**: 占位符与真实值的映射关系存入 Redis，关联到 request_id
- **FR-2.5**: 在 LLM 响应返回时，从 Redis 读取映射表，将响应中的占位符还原为真实值（Rehydration）
- **FR-2.6**: 流式响应场景下，实现带缓冲的占位符边界检测与还原
- **FR-2.7**: 支持会话级映射（同一 session_id 内多轮对话使用一致的占位符映射）

### FR-3: 智能路由决策层

#### FR-3A: Prompt 难度评估
- **FR-3.1**: 规则前置引擎 — 对极简请求（prompt 长度 < 30 字且命中寒暄词库）直接路由到本地小模型，延迟 < 1ms
- **FR-3.2**: 模型推理评分 — 对非寒暄请求，使用 RouteLLM 分类器（mf/bert）进行单次本地推理，输出 prompt 复杂度分数 [0, 1]
- **FR-3.2a**: 打分输入可配置 — 支持两种模式：`masked`（用脱敏后文本打分，安全优先，默认）、`original`（用原文打分，精度优先，仅限本地推理不出网）

#### FR-3B: 模型能力自动评估
- **FR-3.3**: 模型参数配置 — 管理员在 YAML 中声明每个模型的属性参数（benchmark 分数、参数量、上下文长度、价格、延迟等）
- **FR-3.4**: 能力分数自动计算 — 系统根据模型参数，通过可配置的加权归一化算法，自动计算每个模型的能力分数 [0, 1]
- **FR-3.5**: 路由区间自动生成 — 根据模型能力分数自动生成 score_range（允许区间重叠），形成路由表
- **FR-3.6**: 人工覆盖 — 管理员可手动修改任意模型的 score_range，覆盖自动计算结果
- **FR-3.7**: 评分权重可配置 — 各评估维度（质量、代码能力、数学能力、上下文长度、性价比等）的权重可通过配置调整，适应不同企业策略

#### FR-3C: 路由匹配与分发
- **FR-3.8**: 区间匹配 — 将 prompt 难度分数与模型能力区间匹配，找出所有候选模型
- **FR-3.9**: 重叠策略 — 当多个模型的区间覆盖同一分数时，支持可配置的选择策略：
  - `lowest_cost`: 选最便宜的（省钱优先）
  - `highest_capability`: 选能力分最高的（质量优先）
  - `round_robin`: 轮询分发（负载均衡）
  - `random`: 随机选择（A/B 测试）
- **FR-3.10**: 配置热更新 — 路由表、阈值、权重变更无需重启服务
- **FR-3.11**: 路由审计日志 — 记录每次路由决策（prompt hash、难度分数、候选模型列表、最终选中模型、策略、时间戳）
- **FR-3.12**: 会话路由策略 — 多轮对话场景下支持三种路由行为，通过配置切换：
  - `sticky`: 同一 session 锁定到第一轮选定的模型（默认，保证对话连贯性）
  - `per_turn`: 每轮独立打分独立路由（适合无关联的单次任务）
  - `escalate_only`: 后续轮次只能升级模型梯度（weak→strong），不能降级（平衡成本与质量）

### FR-4: 安全合规拦截层

- **FR-4.1**: 请求前置拦截 — 检测 Prompt Injection / Jailbreak 攻击模式
- **FR-4.2**: 请求前置拦截 — 敏感词过滤（可配置敏感词库）
- **FR-4.3**: 响应后置拦截 — 检测 LLM 返回内容中的有害/违规信息
- **FR-4.4**: 拦截后返回标准化错误响应（HTTP 400 + 错误描述），不透传至 LLM
- **FR-4.5**: 支持三种拦截模式：strict（严格拒绝）、interactive（提示用户确认）、permissive（记录但放行）

### FR-5: 灾备容错层

- **FR-5.1**: 自动捕获 LLM API 的 429 (Rate Limit)、503 (Service Unavailable)、Timeout 错误
- **FR-5.2**: 触发灾备时，在 50ms 内将请求漂移到配置的候选模型
- **FR-5.3**: 支持优先级排序的 Failover 链（如 GPT-4o → Claude 3.5 → DeepSeek）
- **FR-5.4**: 灾备事件记录告警日志

### FR-6: 可观测性

- **FR-6.1**: 分步骤耗时打点（脱敏耗时、路由决策耗时、LLM 响应耗时、还原耗时）
- **FR-6.2**: 路由决策审计日志（哪个 prompt 被路由到哪个模型、分数多少）
- **FR-6.3**: Token 消耗统计（按 API Key / 用户 / 模型维度聚合）
- **FR-6.4**: 健康检查端点 `/health`

## 非功能性需求 (Non-Functional Requirements)

### NFR-1: 性能

- **NFR-1.1**: 网关附加延迟（脱敏 + 路由决策）≤ 20ms（不含 LLM API 网络耗时）
- **NFR-1.2**: 单实例支撑 ≥ 1000 QPS 并发代理
- **NFR-1.3**: 路由规则引擎延迟 < 1ms
- **NFR-1.4**: RouteLLM 模型推理延迟 < 10ms

### NFR-2: 安全与合规

- **NFR-2.1**: Redis 隐私映射表 TTL = 30 分钟，到期物理擦除
- **NFR-2.2**: 网关本地不持久化任何用户明文 PII 数据
- **NFR-2.3**: 审计日志中不记录原始 PII，仅记录 prompt hash 和脱敏后内容

### NFR-3: 可靠性

- **NFR-3.1**: ClawVault 伴生进程挂掉时，网关进入降级模式（bypass 脱敏但记录告警）
- **NFR-3.2**: Redis 不可用时，拒绝需要脱敏的请求并返回 503
- **NFR-3.3**: RouteLLM 分类超时时，默认路由到中档模型（DeepSeek）

### NFR-4: 部署与运维

- **NFR-4.1**: Docker 单容器部署（Supervisor 管理 ClawVault + LiteLLM 两个进程）
- **NFR-4.2**: 通过 Unix Domain Socket 实现 LiteLLM 与 ClawVault 的 IPC 通信
- **NFR-4.3**: 配置热更新（模型池、阈值、敏感词库变更无需重启）
- **NFR-4.4**: 支持 Kubernetes HPA 横向扩缩容

---

## 约束条件

- 基于 LiteLLM Proxy 作为网关骨架（Python / FastAPI）
- PII 检测引擎使用 Microsoft Presidio + 自定义中文 Recognizer
- 智能路由使用 RouteLLM 的分类器（仅打分，路由逻辑自研）
- ClawVault 作为安全伴生进程处理脱敏/还原/合规检测
- Redis 作为隐私映射表的唯一存储
- 通信方式：LiteLLM ↔ ClawVault 通过 UDS（/var/run/clawvault.sock）

## 第二期规划 (Phase 2 Roadmap)

### FR-P2-1: 企业自定义敏感信息规则管理

- **FR-P2-1.1**: 企业自定义关键词脱敏 — 支持配置企业不允许外泄的关键词（项目代号、内部系统名、财务术语等），命中时进行占位符替换
- **FR-P2-1.2**: 企业自定义正则规则 — 支持配置自定义正则模式（如内部工号格式、内部 IP 段、源代码片段检测）
- **FR-P2-1.3**: 分类动作策略 — 每条规则可配置独立的处理动作：`mask`（脱敏替换）、`block`（拦截拒绝）、`alert`（告警但放行）
- **FR-P2-1.4**: Web 管理界面 — 提供可视化配置界面，支持规则的增删改查、分类管理、启停控制
- **FR-P2-1.5**: 规则热更新 — 规则变更后实时生效，无需重启服务
- **FR-P2-1.6**: 规则命中统计 — 记录每条规则的触发次数、最近触发时间，辅助运维调优
